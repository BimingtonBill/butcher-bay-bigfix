# v0.2 input, timing, audio and AA — EU 1.1 AMD64

Static research, 2026-10-29. No game process was launched, no game DLL was
loaded, and no game file was changed. All addresses below are **module RVAs**.

The mouse uses **DirectInput 7 buffered relative input**, with a 100-record
buffer. Its reader drops the entire returned batch on buffer overflow. Raw
input should replace motion at that reader's event boundary, retaining the
engine's bindings, wheel/buttons and sensitivity path. This is a confirmed
loss mechanism, **not proof that every reported >125 Hz twitch is overflow**.
The exact `SENSITIVITYX/Y` config-to-command mapping remains unresolved.

The main simulation scheduler uses **QPC and an accumulator with repeated
steps and a fractional remainder**, rather than one physics step per rendered
frame. There is no evidence here justifying a mandatory 60 FPS cap. Offer an
optional limiter in the existing SwapBuffers hook; do not claim complete
high-FPS physics safety from this static inspection.

Audio uses **DirectSound8**, including secondary buffers without
`DSBCAPS_GLOBALFOCUS`. Adding that flag to secondary-buffer creation is the
minimal candidate for background audio. A live trace must distinguish Windows
focus muting from any additional engine suspension.

AA uses **WGL ARB multisample pixel formats**. The console setter enables
multisampling and requests a video restart; it is not merely a GL toggle.
Select MSAA **before the real window's first SetPixelFormat**, after obtaining
WGL extension functions through a disposable bootstrap context. Borderless is
compatible with MSAA, but the existing focus and window hooks must survive any
window recreation. AMD failure is not diagnosed by the available NVIDIA run.

| Question | Confidence | Recommended interception |
|---|---|---|
| Mouse acquisition/overflow | High | `MSystem+0x9BAC0` mouse poll, or its identified device's GetDeviceData slot `+0x50`; inject engine motion event `0xFB` through `DownKey` |
| Exact >125 Hz cause; User.cfg mapping | Medium / unresolved | Trace returned HRESULT/counts, scan queue and final look arguments before making an acceleration claim |
| Timing scheduler / whole-game safety | High / unproven | Optional limiter in existing `gdi32!SwapBuffers` hook (`RndrGL+0x4E77F` page-flip caller; also `0x48745`) |
| DirectSound flags / sole mute cause | High / medium | Intercept DirectSound8 creation, then `IDirectSound8::CreateSoundBuffer` (`+0x18`), add GLOBALFOCUS only to secondary descriptors |
| AA creation path / AMD cause | High / unresolved | Renderer ChoosePixelFormat/SetPixelFormat IATs and wglGetProcAddress-returned chooser, with format validation |

## 1. Mouse

### Creation, format and polling — high confidence

`MSystem+0x9E7B0` is exported `CInputContext_DInput`'s constructor. It loads
`DINPUT.DLL` (literal `0x1DEF00`) and resolves `DirectInputCreateA` at `0x9E858`.
Exported `DI_CreateDevices`, `0x9F0F0`, requests version 7, falls back to 3:

```asm
; MSystem.dll
9F256 mov edx, 0x700
9F25F call rax
9F263 je 0x9f327
9F273 mov edx, 0x300
9F27C call qword ptr [rsi + 0xb28]
```

`IN_Mouse_UseDI` is read with default **1** at `0x9F3E0`–`0x9F3F1`.
`IN_Mouse_UsePad` defaults to zero. The ordinary mouse is constructed by
`DI_CreateDevice(...,"CDI_Device_Mouse",GUID_SysMouse,0)` at `0x9F46D`.
GUID at `0x219F10` is `6F1D2B60-D5A0-11CF-BFC7-444553540000`.
RTTI identifies mouse vtable `0x1D5458`: `+0x30 -> 0x9B9D0` initialization,
`+0x48 -> 0x9BAC0` polling. Update `0x9F620` calls each device's poll at
`0x9F797`; its later slot `+0x50` is a no-op for ordinary mouse.

```asm
; MSystem.dll
9BA5A mov edx, 0x64
9BA62 call qword ptr [rax + 0x38]
9BA68 lea rdx, [rip + 0x142da1] ; format RVA 1DE810
9BA72 call qword ptr [r11 + 0x40]
9BA84 mov r8d, 5
9BA90 call qword ptr [rax + 0x68]
```

The engine helper `0x9B710` builds DIPROPDWORD `{dwSize=20,dwHeaderSize=16,
dwObj=0,dwHow=DIPH_DEVICE,dwData=100}` and calls DI SetProperty (`+0x30`)
with pseudo-GUID `DIPROP_BUFFERSIZE=1`. Helper `0x9B760` calls SetDataFormat
(`+0x58`). Format `0x1DE810` is `{size=32,objectSize=24,flags=2,dataSize=20,
objects=11,pad=0,objectArray=0x10298800}`: relative-axis, three LONG axes plus
eight buttons, i.e. a **DIMOUSESTATE2-shaped format**. This is compatible with
the extended standard mouse format, not proof of its original C symbol name.
SetCooperativeLevel (`+0x68`) receives **5 = EXCLUSIVE | FOREGROUND**. It then
Acquires (`+0x38`) if cooperation succeeds. This is not background input.

```asm
; MSystem.dll
9BAE6 mov dword ptr [rsp + 0x40], 0x64
9BAFD lea edx, [rbp + 0x10] ; legacy 16-byte event record
9BB04 call qword ptr [rax + 0x50] ; GetDeviceData
9BB07 cmp eax, 0x8007001e ; INPUTLOST
9BB12 cmp eax, 0x8007000c ; NOTACQUIRED
9BB1D test eax, eax
9BB1F jne 0x9bece
9BE7D add r12, 0x10
9BE81 cmp r14d, dword ptr [rsp + 0x40]
9BE86 jb 0x9bb90
```

One GetDeviceData call per mouse poll, up to **100 events**, no drain-until-empty
loop. `0x9BEE6` reacquires for the two named failures. **S_FALSE / overflow=1
falls into the nonzero exit**, discarding valid records returned with overflow.
The 16-byte layout is legacy DIDEVICEOBJECTDATA, not DI8's x64 24-byte layout.
Offsets **0,4,8,12–19** are X,Y,Z,buttons. Relative axes are buffered; this poll
does not use immediate GetDeviceState. Other device classes do use state reads;
their existence does not make the ordinary mouse immediate.

### Deltas, sensitivity and acceleration — partly resolved

`0x9BBBD` handles X and `0x9BCAC` handles Y. Each forwards the signed data
without a speed-dependent scaling curve through the input context's `DownKey`
slot `+0x58`. Event code is `(deviceIndex<<16)|0xFB`; X and Y occupy the last
two integer arguments. It also submits `0xFA` position notifications; buttons
and wheel retain their own codes. Timestamp at record `+8` is converted through
**float then double**, divided by 1000 (`0x1DE6E0`); timestamps are not QPC.
This loses timestamp precision at long system uptimes, but is not evidence of
a 125 Hz threshold or integer truncation of motion.

```asm
; MSystem.dll
9BBDB mov eax, dword ptr [r12]
9BBE5 mov dword ptr [rsp + 0x28], eax
9BBF1 add edx, 0xfb
9BBF7 call qword ptr [rbx + 0x58]
1207D8 cmp edi, 0xfb
1207E0 add dword ptr [rbx + 0xa84], esi
1207EC add dword ptr [rbx + 0xa88], ebp
120A20 mov rax, qword ptr [rcx + 0xa84]
120A2C mov dword ptr [rcx + 0xa84], eax
120A32 mov dword ptr [rcx + 0xa88], eax
```

`GetMouseMove` (`0x120A20`) returns and clears accumulated XY; the zero comes
from `xor eax,eax` at `0x120A2A`, after the return pair has been copied.
`DownKey` also queues a scan event before accumulating. `QueueScanKey` at
`0x1214B0` returns false if its ring is full (`0x121517`–`0x121525`), another
packet-rate-sensitive boundary worth counting; capacity has not been mapped.

`SbzEngine+0xAD59`–`0xAD8F` installs binding **`mousemove -> look arg0,arg1`**.
`GameWorld+0xD6DE` registers `%slook<f_expr>,<f_expr>` with thunk `0x3C40`,
which calls virtual slot `+0xAE8`. RTTI `CWClient_Mod` primary vtable `0x1DEF08`
maps that slot to **`GameWorld+0xC910`**:

```asm
; GameWorld_Win64_AMD64.dll
C994 mulss xmm7, dword ptr [rbx + 0x20b4]
C99F mulss xmm6, dword ptr [rbx + 0x20b0]
C9AD mulss xmm7, dword ptr [rip + 0x1d1bd3] ; -32
C9B5 mulss xmm6, dword ptr [rip + 0x1d1bc7] ; +32
CA0C call 0x7db50
CA1C call qword ptr [r11 + 0x928]
```

These per-axis gains are populated from profile **`CONTROLLER_SENSITIVTY`**
(original spelling) at `0x4179`–`0x41AF`; the profile invert flag changes the
Y gain. They must **not** be relabelled `SENSITIVITYX/Y`. The reference User.cfg
contains X=0.16/Y=0.06, but neither exact key occurs as an ASCII/UTF-16 literal
in the seven modules. Their binding/parser/data-driven path is unresolved.
The traced poll, accumulation and `look` scaling contain no explicit mouse
smoothing or velocity curve. This does not prove the entire command/simulation
path has no acceleration. Controller nonlinear/deadzone routines elsewhere
(e.g. `MSystem+0x9D020`) are not evidence of mouse acceleration.

When `IN_Mouse_UseDI=0`, `RndrGL+0x47D19` sets context flag `+0x6A0 bit 2`.
WM_MOUSEMOVE then reaches `0x4A4E6`: GetCursorPos, subtract saved coordinates
(`+0x6B4/+0x6B8`), recenter via SetCursorPos, inject the same `0xFB` delta
at `0x4A5A3`. That path can include Windows pointer acceleration and pixel/DPI
effects. It is disabled by default; it must not run alongside raw motion.
No RawInput import was identified in the seven original modules.

**Why high polling can hurt:** a finite event buffer, one batch per Update,
discard-on-overflow, and a second finite scan queue are concrete mechanisms.
At 8 kHz, two axis events/report and 60 updates/s can exceed 100 records;
1 kHz normally need not overflow at that cadence, but stalls can. Do not claim
an exact universal 125 Hz cutoff, sign-extension bug or smoothing bug without
the trace below. Raising only the buffer size does not fix dropping overflow
batches or establish acceleration-free behavior.

**Hook recommendation:** collect foreground raw relative motion on the window
message thread (`RegisterRawInputDevices`, usage 1/2), accumulate signed counts
in 64 bits, consume once per engine mouse poll. `WM_INPUT/GetRawInputData` is
the simplest start; for high-rate batching drain `GetRawInputBuffer` on that
same owning thread, accounting for the current message exactly once. Do not
multiply counts by dt, smooth, or use cursor pixels. Replace X/Y at
`MSystem+0x9BAC0` / the identified mouse's GetDeviceData boundary and submit
the existing `DownKey(...0xFB...,dx,dy)` semantics, retaining normal wheel,
button, position and menu handling and the downstream sensitivity/inversion.
The COM-boundary alternative must honor the **16-byte format**, queue/peek
semantics and device identity; do not blanket-hook all DI devices. Clear raw
counts on focus/capture changes and device/window recreation. Do not double
deliver DI axes and raw axes. Registering raw input can interact with Windows'
DI implementation; verify acquisition and button delivery rather than assuming
both registrations coexist. Avoid RIDEV_NOLEGACY until menu behavior is proven.

## 2. Frame timing

### Clock and simulation scheduler — high confidence, tick rate unresolved

`SbzEngine+0x5AB60` returns QPC's 64-bit counter. `0x5AB90` initializes its
frequency conversion using QPF; `0x5AB80` returns the reciprocal-frequency
float at timer `+0x24`. The scheduler (`0x37C00`, called at `0x483A0`) multiplies
counter by that reciprocal in **double**, subtracts a double time origin, and
converts the elapsed duration to float. It does not first truncate to DWORD
milliseconds. MSystem has analogous QPC accessors (`0x4200/0x4209`). GetTickCount
sites exist (including CRT cookie initialization), but are not this frame clock.
No timeGetTime import was found in the seven-module scan.

```asm
; SbzEngine.exe
5AB69 call qword ptr [rip + 0x4d651] ; QueryPerformanceCounter
5AB9E call qword ptr [rip + 0x4d614] ; QueryPerformanceFrequency
5ABDE divsd xmm0, xmm1
37D2C mulsd xmm1, xmm2
37D34 subsd xmm0, qword ptr [rdi + 0xb8]
37D3C cvtsd2ss xmm6, xmm0
37D44 comiss xmm9, xmm6 ; xmm9=0
37D50 comiss xmm6, dword ptr [rip + 0x71dbd] ; 1.0 seconds
37D59 movsd qword ptr [rdi + 0xb8], xmm1
37D61 movaps xmm6, xmm8
```

Negative duration becomes zero. **Above 1 second**, time origin is reset and
duration becomes one step (`xmm8`); it is not simply clamped to 1 second.
`xmm8` comes from the object at scheduler `+0x238`, virtual `+0x568` at
`0x37CF1`. Its concrete runtime type and the numeric tick period are not
established here; do not resolve it through a client vtable just because a
client has the same slot number.

```asm
; SbzEngine.exe
37EA1 comiss xmm6, xmm8
37EA5 jb 0x38154
37EAB cvtss2sd xmm14, xmm8
37EF4 subss xmm0, xmm8 ; xmm0 initially zero
37EF9 addss xmm6, xmm0 ; subtract one step from remainder
37F02 addsd xmm1, qword ptr [rdi + 0xb8]
37F0A movsd qword ptr [rdi + 0xb8], xmm1
37F7B call qword ptr [rax + 0x718]
37F96 divss xmm1, xmm8
37F9B call qword ptr [rax + 0x710]
38129 comiss xmm6, xmm8
3812D jae 0x37ef0
38165 divss xmm6, xmm8
38182 call qword ptr [r11 + 0x730]
```

This is repeated-step scheduling and a fractional remainder path. Flags at
scheduler `+0x148` enable an additional simulate-ahead/fractional path when
elapsed < step (`0x37D65`–`0x37E9C`). It is therefore too strong to claim every
physics operation is fixed dt. No max-substep count was identified in the
shown loop; the >1-second reset bounds ordinary catch-up indirectly, provided
the step is positive. Numeric step, physics integration and all animation,
audio and input consumers still need measurement. In particular, this evidence
does **not** establish a >1000 FPS zero-ms bug or a >60 FPS physics defect.

`RndrGL+0x2D520` resolves wglSwapIntervalEXT into renderer `+0x3EA0` and
wglGetSwapIntervalEXT into `+0x3EA8`. `0x2D4F0` and initialization at `0x2D596`
call the setter with **0 or 1** according to `+0x3EB0`. Vsync therefore exists,
but is display/driver dependent and cannot impose 60 FPS on a 180 Hz display.
Present calls are `RndrGL+0x48745` and `0x4E77F`. The latter belongs to
page-flip override `0x4E520` (display vtable `+0xC0`), including its deferred
mode handling. Do not assume the first enumerated call site is the main swap.
That page-flip path also sleeps 100 ms when another process is foreground,
which matters when checking background audio streaming/refill cadence.

**Recommendation:** no mandatory 60 FPS default based solely on this research.
Add optional MaxFPS at the existing SwapBuffers hook, gated to the main game
window/context/thread, leaving time APIs and engine dt intact. Use QPC absolute
deadlines and a high-resolution waitable timer when available, with a supported
fallback; account for original SwapBuffers/vsync blocking, reset the schedule
after focus/loading gaps, and never busy-catch-up missed presentation deadlines.
Avoid limiting bootstrap contexts or adding a second limiter. Validate 60,
120/180, uncapped and an optional >1000 FPS diagnostic run in an opening-dock
fixture only. The Dark Athena timing bug cannot be imported as evidence here.

## 3. Audio focus

### DirectSound path — high confidence

`MSystem+0xAFFF0` loads `DSOUND.DLL` and resolves `DirectSoundCreate8` at
`0xB0182`; an optional EAXDirectSoundCreate8 path also exists. This is not an
identified OpenAL backend. `0xAE740` creates the object; `0xAF020` initializes
the HWND and buffers. Both normal/recovery paths select priority cooperative
level:

```asm
; MSystem.dll
AF2B1 mov rcx, qword ptr [rbx + 0x6f8]
AF2BB mov r8d, 2
AF2C1 mov rdx, qword ptr [rbx + 0x6f0]
AF2C8 call qword ptr [rax + 0x30] ; SetCooperativeLevel(HWND,DSSCL_PRIORITY)
AF3AD mov r8d, 2
AF3BA call qword ptr [rax + 0x30]
ACC31 mov eax, 0x500e0
ACC36 mov ecx, 0x700b0
ACC3E cmovne eax, ecx
ACC41 mov dword ptr [rsp + 0x914], eax ; DSBUFFERDESC.dwFlags
A54DC call qword ptr [rax + 0x18] ; CreateSoundBuffer
```

The streamed/constructed secondary descriptor at `0xACC26` has `dwSize=40`
and flags `0x500E0` or `0x700B0`. Neither includes **GLOBALFOCUS=0x8000**.
`GETCURRENTPOSITION2=0x10000` must not be confused with GLOBALFOCUS.
`0xACD49 -> 0xA50D0 -> 0xA54DC` creates it. Cached waveform paths can instead
DuplicateSoundBuffer (`0xA5162/0xA522E`); their original creation also needs
coverage. Primary descriptor `0xAD017` uses flags **0x11 = PRIMARYBUFFER |
CTRL3D**, passed through the same `0xA50D0` wrapper. Do not add GLOBALFOCUS to
primary buffers.

Sound OnMessage `0xA04E0` tests internal message **0x103 = new main window**,
updates HWND and initializes sound if necessary. It contains no focus mute.
Renderer WndProc `0x49580` has explicit WM_KILLFOCUS handling at `0x497C0`:
release capture, minimize exclusive mode, mark suspended/queue mode 0 at
`0x49816`. WM_SETFOCUS at `0x49831` resets keys and restores pending mode.
No explicit WM_ACTIVATEAPP mute branch was identified there. v0.1 borderless
already bypasses the entire KILLFOCUS handler in `src/window_mode.cpp`; that
cannot supply a missing DirectSound buffer capability.

**Recommendation:** option-gated interception of the dynamically resolved
DirectSoundCreate8 return, then that object's `CreateSoundBuffer` slot `+0x18`.
Copy/validate DSBUFFERDESC, OR GLOBALFOCUS for **secondary** buffers only,
forward other flags and HRESULT unchanged, cover EAX creation if selected and
log duplicates. Do not change priority cooperative level to fake input focus,
and do not globally swallow focus messages. Trace actual Stop/volume/pause calls
on focus loss before adding any engine detour. If buffers continue but the
engine stops refilling them, GLOBALFOCUS alone will not solve background audio;
that runtime distinction is still open.

## 4. Anti-aliasing

### Settings, WGL attributes and restart — high confidence

`GL_ADVPIXELFORMAT` is read at `RndrGL+0x47B8E` with default **0**, stored as
boolean context `+0x6BC`. Initial samples `+0x6E0` and nominal max `+0x6E4`
are zero. After a context is current, `0x4D49F` onward resolves:
`wglGetPixelFormatAttribivARB` -> `+0x6C0`, `...fvARB` -> `+0x6C8`,
`wglChoosePixelFormatARB` -> `+0x6D0`, `glSampleCoverageARB` -> `+0x6D8`.
If **glSampleCoverageARB** is nonnull, `0x4D4F4` sets nominal max to **16**;
this is not a device-supported maximum query. `vmultisampletaps<i_expr>`
registration `0x4633E`–`0x4634F` uses thunk `0x45740 -> slot +0x180 -> 0x49340`.

```asm
; RndrGL.dll
49364 cmp byte ptr [rcx + 0x6bc], 0
4938B cmp qword ptr [rcx + 0x6d8], 0
493B3 mov eax, dword ptr [rcx + 0x6e4]
493BB cmovl ebx, eax
493C2 cmovs ebx, esi
493D5 mov ecx, 0x809d ; GL_MULTISAMPLE
493DA call qword ptr [rip + 0x45828] ; glEnable
493ED mov dword ptr [rdi + 0x6e0], ebx
4940C or dword ptr [rdi + 0x6a0], 0x100
```

The setter clamps to [0,nominal max], toggles GL_MULTISAMPLE, records taps,
marks reconfiguration, caches the mode and writes **`OPTG\UPDATEFROMENV=1`** through
environment setter at `0x49516`. Thus a late console/exec command may recreate
the display/window/context. A first-frame glEnable alone cannot allocate MSAA.
Page-flip consumes pending mode `+0x718` at `0x4E7D8`; SetMode `0x4DB20`
honors bit `0x100` to force reconfiguration even when the mode is unchanged
(see the existing display/window RE). This connects the AA setter's flags
to the renderer lifecycle rather than relying on the command name.

`RndrGL+0x4B0C0` builds the advanced format request; actual chooser call is
`0x4B35A`, SetPixelFormat `0x4B600`. Legacy fallback is `0x4AA90`, calling
ChoosePixelFormat at `0x4AC0B`, SetPixelFormat at `0x4AD6F`.

```asm
; RndrGL.dll
4B207 mov ecx, dword ptr [rbp + 0x6e0]
4B211 mov eax, dword ptr [rbp + 0x6e4]
4B225 mov dword ptr [rsp + rax*4 + 0x4f0], 0x2041
4B236 mov dword ptr [rsp + rax*4 + 0x4f0], 1
4B247 mov dword ptr [rsp + rax*4 + 0x4f0], 0x2042
4B258 mov dword ptr [rsp + rax*4 + 0x4f0], ecx
4B35A call qword ptr [rbp + 0x6d0]
4B5F6 mov edx, dword ptr [rsp + 0x14f0]
4B600 call qword ptr [rip + 0x42a62] ; SetPixelFormat
```

Attributes include DRAW_TO_WINDOW `0x2001=1`, SUPPORT_OPENGL `0x2010=1`,
double buffer or stereo from window flags, RGB/depth/stencil/alpha bits,
FULL_ACCELERATION `0x2003=0x2027`; when taps>0, **SAMPLE_BUFFERS=0x2041=1,
SAMPLES=0x2042=min(request,nominal max)**. Up to 256 formats are requested,
and the **first** returned format is used. Failure/zero-format paths report
errors, but can fall through when GetLastError is zero (`0x4B385`, `0x4B4CF`)
instead of an explicit lower-sample retry. This fragile path warrants guarding.

**AMD:** no vendor-specific sample attributes are necessary in this request.
Plausible failures include the ARB-suffixed coverage-function gate, unsupported
requested format constraints/counts, zero formats/weak failure handling, or
later rendering behavior. None is proven as the AMD root cause. The hard-coded
16 ceiling explains why accepting 16 is not evidence that 16 works. Do not
promise AMD support or supersampling as part of v0.2; that belongs to v0.3.

**Recommendation for BigFix.ini:** validate a small sample-count choice
(off/2/4/8), enumerate/query real formats, prefer the requested count with
explicit lower-count/off fallback and log what was actually selected. Reuse
the game's advanced path when safely initialized, or intercept its renderer
ChoosePixelFormat/SetPixelFormat imports and chooser returned by
wglGetProcAddress. The initial legacy call may occur **before** WGL extensions
are available: obtain them with a disposable hidden bootstrap window/context,
restore the previous current context, then select the real format before the
real window's first SetPixelFormat. Never call SetPixelFormat twice on the same
window. Hooking only wglChoosePixelFormatARB misses default
GL_ADVPIXELFORMAT=0; hooking only ChoosePixelFormat misses advanced restarts.
For every real new context verify GL_SAMPLE_BUFFERS/GL_SAMPLES and enable
GL_MULTISAMPLE. Preserve depth/stencil/double-buffer requirements.

MSAA is a window framebuffer choice and works in borderless; it does not need
ChangeDisplaySettings or exclusive fullscreen. Do not confuse v0.1's
fullscreen-tagged synthetic mode with an exclusive requirement. Preserve the
borderless policy, physical dimensions, WndProc/raw-input registration and
main-HWND tracking on a video restart. Prefer choosing the format correctly on
initial creation over forcing a console-driven restart after the menu appears.

and opening dock, without later levels. Include QPC timestamps, tid, caller
module+RVA, window/context/device identity and a hard line budget; aggregate
